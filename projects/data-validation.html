Comparing the City’s Two Daily Shelter Sources

A source-timing review in progress

How BonQuery compares and combines Toronto’s daily shelter webpage and detailed open-data file while their timing and definitions are clarified.
Author

Miriam Marling

The City publishes a 4 a.m. shelter snapshot in two places: a daily webpage and a detailed open-data file. BonQuery compares the sources so we can reproduce the published data and continue showing recent totals if one source is delayed.

Interpretation is under review. The two sources can show different values for the same date. BonQuery does not yet know whether this reflects different extraction times, later revisions, or different operational definitions. We are preserving the exact comparisons and will ask the City privately before publishing a conclusion about which source should be treated as correct.

The large table below keeps one detailed example from May 14, 2026. The City’s webpage no longer shows that date.

function n(v)   { return v !== null && v !== undefined ? (+v).toLocaleString() : "—" }
function pct(v) { return v !== null && v !== undefined ? (+v).toFixed(1) + "%" : "—" }

// Known-difference keys (capacity/rate only — ind and occ match)
KNOWN_CAP_KEYS = new Set(["mix_emerg","men_emerg","wom_emerg","yth_emerg","emerg_total","singles_total"])

function mark(bqVal, cityVal, isCapOrRate, key) {
  if (cityVal === null || cityVal === undefined) return ""
  if (bqVal === null || bqVal === undefined) return ""
  const match = Math.abs(+bqVal - +cityVal) < 0.11
  if (match) return `<span style="color:var(--bq-success);font-weight:bold">✓</span>`
  if (isCapOrRate && KNOWN_CAP_KEYS.has(key))
    return `<span style="color:var(--bq-caution);font-weight:bold" title="Different number. See the explanation below.">*</span>`
  return ""
}

What might explain the differences?

The reason has not yet been confirmed. The webpage may use a newer extract from the City’s operational system than the open-data file, or the two outputs may apply different update times or definitions. BonQuery will ask the City to clarify this before drawing conclusions.

The grey funded number is how many beds the City paid an operator to run. The City webpage does not show this number.

Every BonQuery number in this table comes from the City’s public data file. We show the two City sources together so people can see where their values differ.

What does “funded but unavailable” mean?

A funded but unavailable bed is a bed the City paid for that was not open to use that day. The City’s data lists reasons such as repairs, pest control, too few staff, or medical isolation.

The City does not show this count on its webpage. BonQuery calculates it like this: funded beds minus beds open to use. This matters most in dangerous weather, when every bed matters.

A program missing from the public data file

On May 14, the City webpage showed 29 people in Bridging & Triage Programs. The public data file did not include this program at all. That means the file alone cannot give the same total as the webpage. BonQuery will ask the City how this program should be represented in the detailed file.

Does the City change old data?

We save a copy of the City’s file each time we update. A computer then checks whether the City changed any earlier row. If it did, BonQuery sends an email. The May 14 numbers have not changed since we first saved them on May 17, 2026.

What this means now

The webpage and open-data file can differ. BonQuery saves the source records so the checks can be repeated, but will not identify either output as wrong until the City clarifies their timing and definitions. Neither source is live bed availability.
